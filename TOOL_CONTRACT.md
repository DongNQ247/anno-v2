# Anno 2.0 tool contract

Local rendering: `label grid IMAGE --cells CELLS` and `label select IMAGE --cells CELLS` accept `--scale auto|1|2|3|4` (default `auto`). Auto uses `ceil(28 / native_subcell_min_edge)`, at least 1; requests needing more than 4 fail with sizing details and guidance to use a coarser cell level. Select computes this from implied 8x8 subdivisions of the selected cells before adding margin (default 0.20). Explicit scales override the 28 px target, but source subpixel cells and labels that cannot fit still fail. Global grid retains its 1024 px thumbnail behavior; numeric scale requires `--cells`.

Local responses include `crop`, `native_crop_size`, integer `scale`, `render_size`, and `readable_labels`. Grid additionally returns `subcell_size` (smallest selected level if levels differ), `parent_cell_count`, `subcell_count`, and `recommended_max_parent_cells: 8`. Geometry remains in original image pixels. `readable_labels` means the coordinate text layout fits, not that object boundaries or annotation quality have been verified. Subgrids exceeding 8 distinct parent cells fail even with an explicit scale; prefer 1–3 adjacent cells around one uncertain edge. Use select for inspection, then visual for the final candidate before verification and mutation.

`anno-contract.yaml` and packaged `templates/contract.json` are generated from the CLI parser by `python tools/generate_contract.py`. `anno capabilities` returns that same contract, including every command, argument, default, schema and error code. `.a4od/contract.yaml` points to the current contract; no `a4od` executable is shipped.

Run project commands from the project root. Supported runtime: Python 3.10+, POSIX; Linux is covered by the automated checks. Dependencies are installed in the project `.venv`. `--help` and `--version` are human-readable; all other successful calls return `ok: true, status: success`, and all request/project errors return `schemas/error.v1.json` with exit code 1. `doctor` errors include the readiness report in `error.details`. Successful response schemas are named after their commands, e.g. `review_next.v1.json`; access them with `anno schema NAME` without needing a project.

Images are confined to `dataset/images/`; corresponding labels are `dataset/labels/<relative-stem>.txt`. Symlinks in managed paths and images sharing the same label path are rejected. Artifacts use `.anno/tmp/<relative-image-filename>/<command>.png`, retaining the extension to avoid path collisions. Rendering writes only artifacts, never labels or review state. `review sheet` is an indexed overview alias, not an approval operation.

Presentation extension: JSON remains the default and the response schemas apply to JSON output. Every command accepts `--format json|text` at any command level; the last occurrence wins. Explicit `--format text` renders readable results on stdout and errors (including their codes and details) on stderr, with the same exit codes and command behavior. An invalid format value returns a JSON argument error. In text mode, `schema` and `capabilities` are indented JSON documents. Help includes descriptions and examples at every command level. Text review progress explicitly distinguishes reviewed activity from approval; queue exhaustion is not an approval claim.

Only the CLI may mutate labels and manifest. `label verify IMAGE --class ID --cells CELLS` returns a token bound to the absolute image path, image bytes, current label bytes, class mapping, project config, candidate class, pixel box and image dimensions. `label bbox add|update` requires `--verification-id TOKEN` and checks it again under the write lock. Obtain a fresh token after each mutation. `delete` requires `--index`; `empty` creates an explicit negative label and refuses to overwrite nonempty labels. Pixel boxes use outward rounding; serialization retains round-trip float precision.

`review audit` has five configurable geometry checks: high IoU >= .8, minimum edge < 5px, containment >= .999, aspect ratio > 20, and out-of-bounds. Config must be complete and valid; command-line overrides affect only that invocation. Missing labels, malformed labels, invalid classes and unreadable images are reported together in `error.details.failures`; such an audit changes no manifest or labels. Empty label files are valid negative images. Audit replaces geometry findings, preserves visual findings and never approves.

`review next` orders flagged, modified, unreviewed, then relative path. `label next` orders flagged then missing labels, excluding modified from new work. Both include open findings where applicable and return `done: true, image_path: null` on exhaustion. They never claim images or persist state; unseen images are treated as unreviewed in memory until the next state-writing command.

`review mark --issue TYPE --message TEXT [--box-index N]` merges findings, deduplicates exact repeats and sets flagged. Findings refer to box indexes at observation time; indexes can shift after deletion, so review the current overlay/list before editing. `review mark --verdict approved [--notes TEXT]` requires a successful audit bound to current content/config, no open geometry issues, and the caller's completed visual review. It archives closed findings, notes and timestamps. The tool cannot itself certify the caller's visual judgment.

Mutations hold an exclusive project advisory lock; readers hold a shared snapshot lock, without claiming images. Writes use fsync and atomic replacement. Label/manifest updates have a durable replay journal. If a write is interrupted, project operations stop with `RECOVERY_REQUIRED`; `anno repair` replays the journal under the lock. Do not edit files while a transaction is pending. The guarantee covers cooperating CLI processes on a local POSIX filesystem, not arbitrary external writers or all network filesystems. Back up images, labels, config, skills and manifest together.

`init [--force]` only creates missing files. Existing files, including customized skills and schemas, are preserved and listed as conflicts. For an existing project, back up first, run init to add missing resources, then migrate any listed resources deliberately; no schema or data migration is silently performed. Old approvals without content fingerprints need a fresh audit and visual review.

`infer` is intentionally unavailable until its runtime, model/class mapping, dependencies and no-overwrite policy have an accepted and tested contract. This release makes no measured accuracy, dataset-scale performance, or token-saving claim.
